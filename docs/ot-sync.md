# 在线文本 OT 同步（0.16.19）

远端编辑与已建立基线的本地副本文本使用同一个文档会话。健康在线保存不再执行四次全文读取；保存才提交操作，普通输入只更新本地草稿。二进制、创建、删除、重命名仍走原有安全同步流程。

## 数据流与确认

- `OtSession` 单独拥有文档版本、已确认内容、一个 inflight 操作、后续已保存 pending 操作及未保存 draft。文本算法来自官方固定提交 `28ad3b03b71cb4311decdcb55c36b33ec10d72db` 的 ShareJS text 类型；来源和 MIT 许可见根目录 `OT_THIRD_PARTY_NOTICES.md`。
- 首次 `joinDoc` 建立内容和版本；断线后带 `fromVersion` 追赶。文档会话在项目生命周期内保留订阅，以便本地副本持续收到变化；这与官网按编辑器生命周期释放订阅不同。已无调用者的 `leaveDoc` 封装已删除。
- 每次保存立即生成增量，若已有 inflight 则组合后续 pending。远端操作依次与 inflight、pending、draft 做双向变换。本地副本保留实际远端操作序列，不用最终全文差分替代操作历史。
- `applyOtUpdate` 的 Socket 回调只确认接收。服务端向当前提交者发送 `{doc,v}`，向其他协作者发送完整操作；恢复历史中的自身操作通过 `meta.source` 识别。两种应用确认都受版本与连接约束。
- 5 秒没有应用确认时携带原始提交版本及 `dupIfSource` 重试；45 秒仍未确认则暂停并保留修改。版本缺口、未知操作类型、服务端 `otUpdateError` 也停止该文档写入。history-ot 不在当前支持范围。

官方依据：[客户端确认、pending/inflight 变换](https://github.com/overleaf/overleaf/blob/28ad3b03b71cb4311decdcb55c36b33ec10d72db/services/web/frontend/js/vendor/libs/sharejs.js)、[5 秒重试与 45 秒期限](https://github.com/overleaf/overleaf/blob/28ad3b03b71cb4311decdcb55c36b33ec10d72db/services/web/frontend/js/features/ide-react/editor/share-js-doc.ts)、[服务端紧凑确认分发](https://github.com/overleaf/overleaf/blob/28ad3b03b71cb4311decdcb55c36b33ec10d72db/services/real-time/app/js/DocumentUpdaterController.js)。

## 编辑器、磁盘与编译

- 磁盘内容与未保存编辑器内容分层处理。远端变化实时合并到脏编辑器，保持未保存状态；干净编辑器通过文件提供器/磁盘变化重新加载，避免人为制造脏文件。
- 程序性编辑使用来源标记抑制回传，并检查文档版本。连续输入、撤销产生的用户变动仍只进入本地草稿。编辑器应用失败时保留当前内容、暂停该会话。
- 本地磁盘采用原有原子写入、旧内容哈希校验与恢复日志。上传等待期间再次保存的新文件不会被旧结果覆盖，下一轮以已持久化提交的保存边界计算增量。
- 编译只保存当前项目的脏文档，等待本轮操作应用确认和有限同步队列；后续事件不会无限延长同一队列屏障。失败时保留旧 PDF。
- 输出面板选择 **Overleaf OT** 可查看 `persist`、`submit`、`confirmed`、`compile-wait` 耗时。日志不包含正文和 Cookie；算法原始错误中的文字被替换为通用错误。这里记录的是阶段耗时，不是浏览器 Network 请求列表。

## 日志与恢复

独立日志保存在扩展 `globalStorageUri/ot/<项目身份哈希>/.overleaf/sync/ot-<文档哈希>.json`，schemaVersion 为 1。身份包括服务器、项目及用户；文件保存确认内容、操作、提交来源和草稿。复用同步存储的操作系统所有权锁、原子替换和 fsync，发送前必须持久化成功。原有本地副本 state/journal 不覆盖、不升级。

| 情况 | 行为 |
|---|---|
| 历史可追赶 | 应用连续操作，识别已经应用的自身提交，使用原始版本和来源去重恢复 |
| 历史不足，但没有任何本地待恢复内容 | 读取新快照重新建立会话 |
| 历史不足，确定只有未发送操作 | 三方合并已保存内容及草稿；成功前归档旧日志，再恢复提交 |
| 离线内容重叠、日志损坏、协议不受支持 | 暂停并保留候选内容，提示人工审查 |
| 旧提交是否应用无法判断 | 不把旧操作改成新版本盲目重发，也不自动覆盖远端 |
| 服务端强制断开 | 停止自动重连；仍使用既有 Retry Connection 入口 |

正常本地副本的快照冲突继续使用已有 Source Control 冲突流程。独立 OT 日志的历史不足重叠冲突目前会暂停并保留日志，**尚未接入该原生合并编辑器作为可直接提交的恢复入口**；需要人工核对后恢复，不能宣称所有异常均可自动恢复。

## 验证边界

单元测试覆盖：官方同位置规则、400 组固定种子的并发收敛、中文/emoji/换行、紧凑确认、完整自身回显、重复消息、版本缺口、5/45 秒计时、断线去重、日志重建、磁盘连续保存、未保存内容隔离、实际远端删除/重插入历史、编辑器事件抑制和编译等待。

已完成构建、lint 和 **243 项**完整单元测试（含独立服务端变换的双客户端收敛用例）。没有在真实 Overleaf 隔离项目与 VS Code 双端同时操作，因此不提供线上延迟承诺。编辑器测试使用 VS Code API 模拟；实际撤销栈分组、光标/选区、保存与外部文件变化交错仍需 GUI 验证。通过公共 WorkspaceEdit 应用远端变化，并不等同于官网编辑器的专用撤销栈集成。

VSIX 由用户自行安装；本轮不安装、不重启当前 VS Code。
